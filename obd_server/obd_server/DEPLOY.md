# Розгортання: Render (сервер) + Neon (PostgreSQL)

Обидва сервіси мають безкоштовні плани. Render засинає після 15 хв без запитів,
перший запит після сну триває близько хвилини. Безкоштовна база Render живе лише 30 днів, тому базу беремо в Neon.

## 1. GitHub
Уся курсова (застосунок, сервер, SQL) лежить в одному репозиторії `obd-health`, корінь це папка `course_work`.
`render.yaml` у корені вказує Render, що сервер знаходиться в `obd_server/obd_server`.
Ключі й `.venv` виключені через `.gitignore`.

## 2. База в Neon
1. Зареєструйся на neon.com, створи проєкт (регіон найближчий, наприклад Frankfurt), назва бази `obd`.
2. На сторінці проєкту натисни **Connect**, скопіюй рядок підключення. Він виглядає так:
   `postgresql://користувач:пароль@ep-xxx.eu-central-1.aws.neon.tech/obd?sslmode=require`
3. Відкрий **SQL Editor**, встав увесь вміст `sql/obd_schema.sql` (з папки `course_work/sql`) і натисни Run.
   Це створить таблиці й розширення `citext`.

## 3. Сервер на Render
1. Зареєструйся на render.com через GitHub.
2. New → **Blueprint** → обери репозиторій (Render прочитає `render.yaml`). Або New → Web Service вручну:
   Build `pip install -r requirements.txt`, Start `uvicorn app.main:app --host 0.0.0.0 --port $PORT`, Plan Free.
3. У змінних середовища заповни:
   - `DATABASE_URL`: рядок з Neon (префікс міняти не треба);
   - `GEMINI_API_KEY`, `BAZAGAI_API_KEY`, `AUTODEV_API_KEY`: ключі з твого `.env`;
   - `SECRET_KEY` Render згенерує сам.
4. Після деплою відкрий `https://НАЗВА.onrender.com/health`. Має бути `{"status":"ok","database":"connected"}`.

## 4. Застосунок
Налаштування → Сервер → `https://НАЗВА.onrender.com` → Перевірити. Після простою перший запит може тривати до хвилини.

## Необов'язково: не давати серверу засинати
UptimeRobot (безкоштовно) може відкривати `/health` кожні 5 хвилин. Це утримує сервер активним і вкладається в ліміт 750 годин на місяць для одного сервісу.

## Важливо
- Дані в Neon окремі від локальної бази: старі тестові поїздки не переносяться.
- Безкоштовні умови можуть змінитися, перед захистом перевір, що сервер живий.
